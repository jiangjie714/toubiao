## 设计专属性判定

**LLM 评估**：功能与语言层是高度专属的，视觉层是通用 B2B 后台的——「行业灵魂穿在通用躯壳上」。最强的专属性资产在领域模型：截标倒计时冲刺、资质临期废标预警、保证金催退、下浮罗盘与 CR3/CR5 供应商集中度、清标一票否决扫描、商机公海池抢单、对公转账附言识别码核销——这些是千里马/剑鱼从业者一眼能认出的行话，任何通用 CRM 套不上。但视觉层与此脱节：蓝白 SaaS 配色 + 渐变横幅 + emoji 图标（52 个文件，直接违反 AGENTS.md 自家规范）+ 营销腔文案混杂，削弱数据平台应有的可信感。信息密度方向正确（列表页预算/中标金额/附件数徽章带正是投标经理要的），但单条记录可叠加 7 类徽章且无主次。

## 总体印象

这个产品的内在行业深度是稀缺资产——50 个数据模型、对公识别码核销、下浮罗盘、清标扫描，都是真实踩进招投标场景才做得出的东西。但它外面裹着三层漏风的壳：**安全底线**（登录页白送超管凭证、付费墙后的手机号在 RSC payload 里裸奔）、**获客漏斗**（商业化计划书的核心增长引擎 SEO 被登录墙整个废掉）、**决策负荷**（29 个导航目的地、15 个支付按钮、10 个详情页操作）。最大的机会不是加功能，而是把已有的深度从这三层壳里解放出来。

## 做得好的 3 点

1. **双轨收银台（pay-cashier-view.tsx）**——把「个人散客秒级扫码 vs 企业对公合规打款」的二元客群理论翻译成同一个界面的两个 tab；4 位识别码大号红字 + 一键复制 + WAIT_VERIFY 状态安抚 + 成功页三个下一步，是对公场景罕见的完整情感闭环。
2. **设计基建克制专业（globals.css）**——@theme 令牌、.data-table 组件套件、全局 :focus-visible、prefers-reduced-motion 全局降级、跑马灯「传达数据实时性而非装饰」的注释自觉，是有纪律的系统底座。
3. **空态即引导**——tracker-kanban-view.tsx 的双层空态（未跟进 vs 筛选无结果）各给明确出路；list/page.tsx 空结果给放宽关键词/清空金额/扩大日期三个具体建议。

## 优先问题（按影响排序）

**P0-1 生产登录页暴露全部角色明文凭证 + mock 认证绕过**
- What：login-form.tsx:20-135 硬编码 8 个账号密码（含 admin/admin123 超管）一键填入面板；登录页 CTA 直链 `/api/auth/wecom/callback?code=mock_wecom_user`，而 wechat-work-oauth.ts:52 对任何 `mock_` 前缀 code 直接登录成功并写会话。
- Why：任何访客可无凭证登录、可拿超管入口；对付费企业客户这等于宣布「你们的商机数据谁都能看」。
- Fix：演示面板用 `NEXT_PUBLIC_DEMO_PANEL !== "production"` 门控；mock 分支加 `NODE_ENV === "development"` 判断；移除登录页 mock 企微按钮；校验 OAuth state 为站内路径。
- 建议：$impeccable harden

**P0-2 SEO 获客漏斗整体断裂：sitemap/robots/JSON-LD 全被登录墙废掉**
- What：middleware 放行 /tender，sitemap.ts 提交 5000 条详情页，详情页精心构造 JSON-LD + canonical + 匿名降级逻辑；但 (site)/layout.tsx:13-14 无条件 `if (!user) redirect("/login")`。
- Why：商业化计划书的核心获客模式是「免费层 SEO 引流 + 地区/类型落地页矩阵」——现在搜索引擎抓到的全是 302 → /login，战略级功能失效。
- Fix：匿名用户访问 /tender/*、/regions/*、/industries/*、/list 渲染受限版（标题+摘要+付费墙），仅工作台类页面强登录；或建 (public) 路由组。
- 建议：$impeccable shape

**P0-3 联系方式「假脱敏」：真实手机号随 RSC payload 发到浏览器**
- What：tender/[id]/page.tsx:143-152 服务端无条件 select phone/email/address 原样传给前端，脱敏靠客户端 maskText() + blur-[2px] 完成。
- Why：权限报告 8.2.1 明文红线「严禁未脱敏数据传浏览器后用 CSS blur 假遮罩」；F12 看 RSC payload 即可批量窃取付费墙后的联系方式——产品最核心付费点形同虚设。
- Fix：服务端按 canViewContacts 分支——false 时仅传 masked 字段，true 才传明文；删除组件内 maskText。
- 建议：$impeccable harden

**P1-4 全站无 404 / error / loading 页面**
- What：`notFound()` 落到 Next 默认英文 404；服务器异常白屏；列表页搜索切换无骨架屏。
- Why：付费用户遇到一次英文 404/白屏的信任损伤远大于省下的三个文件。
- Fix：品牌化 not-found.tsx（+搜索框+热门公告）、error.tsx、list/loading.tsx 骨架屏。
- 建议：$impeccable harden

**P1-5 定价页决策超载：15 个支付按钮、无推荐档、无周期切换**
- What：pricing/page.tsx:148-198 每卡渲染微信月/支付宝月/微信年/支付宝年/对公 5 个按钮，4 卡同屏 15 个 CTA；无「最受欢迎」标记，无月/年 toggle。

- Fix：月/年切换 toggle，每卡收敛 1 主 CTA + 1 对公次级链接，渠道选择收进收银台；加推荐 badge；企业两档单独分区。

## 启发性问题

1. **登录墙到底保护什么？** 当前它挡住的是搜索引擎和潜在付费用户，却没挡住 mock OAuth 和明文密码——三道闸的方向恰好反了。如果「摘要公开 + 明文付费」是千里马验证过的漏斗，公开面应该比现在宽得多。
2. **29 个导航目的地都值得一级入口吗？** 工作台 14 项中跟进看板/日历/CRM/复盘功能高度重叠（都是「商机推进」），能否合并为一个「投标工作台」首页 + 二级 tab，把导航压回 ≤7 项？
3. **详情页的主角是谁？** 如果投标经理 30 秒内只做一件事——判断「投不投」，那「赢面评分 + 截止倒计时」应该是唯一视觉焦点，其余全部降级。
4. **红色焦虑需要「绿色安抚」对冲吗？** 四条预警线（截标/配额/资质/保证金）都在制造紧迫，却没有任何「已完成/已安全/已规避损失」的正向反馈——长期使用会让用户对红色脱敏。
5. **emoji 与营销腔是不是同一个根问题？** 「🚨 48h 临期冲刺」「作战指挥室」本质都是用廉价手段模拟「紧迫感与专业性」——而下浮率、胜率、滞留天数这些结构化数据才是对投标经理的专业说服力。让数据说话，把修辞删掉？
