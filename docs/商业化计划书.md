## 第一章 执行摘要

**一句话定位**：把标讯通从「内部工具形态的招投标公告聚合站」升级为「面向企业与个人收费的结构化标讯数据服务平台」——以中等价格、结构化数据、自助化体验切入由千里马（高价企业订阅）与剑鱼标讯（低价个人订阅 + 高价企业版）验证过的市场。

**三大差距结论**（详见第二章）：

| 维度 | 现状 | 商业化所需 |
|---|---|---|
| 数据丰富度 | Tender 仅 8 个业务字段，无金额/编号/行业/附件/原文快照 | 15+ 结构化字段、项目主数据聚合、附件存储 |
| 来源管理 | 全局单一定时器驱动 2 个源，无每源调度/限速/代理/健康分/告警 | 精细化配置中心 + 采集技能 v2 + 20+ 来源 |
| 商业化设施 | 全库零商业化代码，不开放注册，无配额概念 | 会员/支付/配额/推送/导出/API 全套 |

**商业模式结论**：三阶段组合——个人会员先行验证付费意愿（自助、零销售成本），企业订阅承接现金流主力，数据 API 在数据量与质量达标后释放存量溢价。定价显著低于竞品锚点（个人 39–99 元/月 vs 剑鱼 29 元/省/月；企业入门 6800 元/年 vs 千里马 7999 元/年起）。

**三阶段路线**：

- **M0（第 1–8 周）采集升级**：采集技能 v2 框架 + 配置中心 MVP + PostgreSQL 迁移，来源 2 → 6，验收日增 ≥500 条、源失效 30 分钟内告警
- **M1（第 9–20 周）商业化 MVP**：会员 + 支付 + 配额 + 订阅推送 + 导出 + 自助注册，来源扩至 10+，付费闭环上线
- **M2（第 21–52 周）规模化**：开放 API、来源 20+、企业多席位/发票/等保，冲刺盈亏平衡

**首年投入估算**：人力 1.5–2 人 + 基础设施约 0.6–1.2 万元/年 + 一次性合规支出 1.5–5 万元（详见第十章）。

## 第二章 现状基线

### 2.1 已有能力

| 能力 | 现状 | 位置 |
|---|---|---|
| 采集框架 | Skills 化：每源一个目录（config.yaml 抓取规则 + SKILL.md 站点档案），通用执行器 | `crawler/` |
| 采集模式 | html（cheerio 选择器）/ json（点路径）双模式；`{page}` 翻页占位、firstPageUrl 首页特化 | `crawler/types.ts` |
| 字段映射 | FieldSpec（selector + attr + regex），列表 7 字段：title/url/date/province/city/purchaser/agency/hint | `crawler/types.ts` |
| 详情抽取 | 正文选择器 + 剔除规则，cheerio 清洗（保留表格结构、链接绝对化）、GBK 自动解码、超时重试 | `crawler/runner.ts`、`fetcher.ts` |
| 在库来源 | 中国政府采购网中央/地方两源、14 个频道，实测稳定（0 解析失败） | `crawler/skills/` |
| 详情结构化 | 正文分类解析（项目信息/资格与要求/时间安排/联系方式/公告说明）+ 表格/链接富内容块 | `src/lib/tender-sections.ts` |
| 前台 | 登录墙内检索（关键字 + 省市级联 + 类型 + 日期 + 分页）、详情、首页 | `src/app/(site)/` |
| 后台 | 仪表盘、公告 CRUD、用户管理（创建/重置/停用）、数据源启停 + 手动触发、抓取日志 | `src/app/admin/` |
| 认证 | bcrypt + JWT(httpOnly Cookie)，middleware + 页面层双层守卫 | `src/lib/auth.ts`、`src/middleware.ts` |
| 数据量 | 293 条公告、覆盖 29 省、来源去重键 `sourceUrl` 唯一约束 | SQLite |

### 2.2 差距清单

**A. 数据丰富度差距**（证据：`prisma/schema.prisma`）

- Tender 仅 8 个业务字段；`expireDate` 在爬虫路径被硬编码为 null（`crawler/runner.ts` upsertTender），仅手动录入可用
- 缺失：项目编号、预算/中标金额、开标时间、行业与采购品目分类、中标供应商、附件、原文 HTML 快照（正文截断 50000 字符且抓取失败仅存占位文本）、结构化联系方式
- 无项目主数据：同一项目的「招标 → 变更 → 中标」公告链无法关联，用户需自行拼凑

**B. 来源管理差距**（证据：`crawler/worker.ts`、`prisma/schema.prisma` CrawlSource）

- 调度：全局单一 cron（`CRAWL_CRON` 默认每 2 小时）驱动所有源，无法按源错峰、调频
- 限速：仅 config.yaml 静态 `requestDelayMs` 单值，无并发数/QPS 分级；`fetcher.ts` 无代理配置位
- 配置管理：config.yaml 只能改文件重新部署；后台对源仅有启停与手动触发，无新建/编辑/热更新/版本化
- 可观测：CrawlSource 仅 6 个状态字段，无健康分、连续失败计数、成功率统计；CrawlLog 无 HTTP 明细与耗时；无任何告警通道
- 可验证性：无 dry-run 测试模式，验证配置只能真跑一轮

**C. 商业化差距**（证据：全库关键字扫描 quota/plan/subscription/payment/api key 零命中）

- 无套餐/订阅/订单模型；User 仅 ADMIN|USER 两级字符串角色
- 无自助注册（管理员手工建号）、无配额、无数据可见性分级
- 无关键词订阅推送、无数据导出、无开放 API 与 API Key 鉴权、无发票账单
- SQLite 单写瓶颈无法支撑多用户并发与 Decimal 金额字段

## 第三章 市场与竞品分析

### 3.1 行业背景

- **政策驱动**：招标投标与政府采购全流程电子化持续推进，依法必须招标项目信息公开法定化，公共资源交易平台整合共享，使招投标信息的**公开可得性**持续提高——这是本类产品的数据基石
- **需求端**：全国每年招标采购项目数百万量级，投标企业（尤其是中小企业销售团队）的核心痛点是「及时、精准地发现商机」：找得慢丢单、信息不全盲投、人工盯网站成本高
- **供给端**：市场已被验证——千里马（老牌，年费数千至两万）与剑鱼标讯（覆盖 C 端到大型企业）均形成规模化收费，说明付费意愿真实存在
- **结构性机会**：竞品以「文本公告罗列」为主，结构化程度浅；中小企业对**千元级年费**的入门档需求未被充分满足

### 3.2 竞品矩阵（2026-09-10 调研快照）

| 维度 | 千里马招标网 | 剑鱼标讯 | 标讯通（目标） |
|---|---|---|---|
| 定位 | 老牌全渠道企业订阅 | C 端免费漏斗 + 企业版 | 中小企业/个人自助 SaaS |
| 个人定价 | 无（直接企业价） | 超级订阅 29 元/省/月、680 元/全国/年 | 黄金 39/月、铂金 99/月 |
| 企业定价 | 普通 7999 / 高级 12999 / VIP 21999 元/年 | 启航 2999 / 商机 7999 / 专家 19999 / 商机速递 50000 / 商机管理 200000 起（元/年） | 标准 6800 / 专业 16800 / 旗舰定制 |
| 数据覆盖 | 全国省市县、2012 年起历史库、拟在建项目、机构库（代理机构 4964 家） | 31 省分站、招标预告→结果全链、采购意向/拟建/专项债线索、文库 | 起步：政采网 2 源 → 规划 20+ 源 |
| 核心功能 | 关键词订阅、邮件推送、企业监控、项目专员人工服务、Excel 历史导出、数据 API | 20 组关键词订阅、附件下载 10 个/月、项目/业主/企业监控、商机规则分发、CRM 集成（高价档） | 结构化详情（分类区块）、订阅推送、导出、API |
| 付费墙 | 7 天前公告免费、联系方式/联系人必须付费 | 基础免费 + 订阅解锁 | 标题/摘要免费，正文联系方式分层 |
| 获客模式 | 电销 + 官网咨询 | 产品自增长 + 免费转付费 | 自助注册 + 内容 SEO + 免费层漏斗 |
| 弱点 | 价格高、界面老化、自助性差 | 高价档功能堆叠、个人档按省收费碎片化 | （我们的挑战）数据覆盖起点低、品牌零 |

### 3.3 差异化机会

1. **价格带空档**：企业入门档 6800 元/年，低于千里马 7999 与剑鱼启航 2999（但权益更全），主打「中小企业销售团队第一套付费标讯工具」
2. **结构化能力**：详情页分类展示（项目信息/资格/时间/联系方式）+ 后续金额/编号/开标时间结构化检索——竞品公告以长文本为主，我们以「字段」交付
3. **自助化**：注册、开通、发票申请全自助，对标千里马「需电销咨询」的重销售模式
4. **垂直深耕**：先选 1–2 个行业（如医疗设备、IT 软件）把行业标签与品目分类做深，形成差异化记忆点

## 第四章 商业模式设计

### 4.1 三种模式对比

| 维度 | 个人会员 | 企业订阅 SaaS | 数据 API / 定制交付 |
|---|---|---|---|
| 目标客户 | 投标专员、自由销售 | 中小企业销售部/投标部（3–20 人） | 软件集成商、咨询机构、数据二次加工方 |
| 客单价 | 299–799 元/年 | 6800–16800 元/年起 | 2 万–20 万/年 |
| 销售链路 | 纯自助，成本≈0 | 内容营销 + 轻电销 | 直销/渠道，链路长 |
| 合规要求 | 低 | 中（合同/发票） | 高（数据授权协议、审计） |
| 支撑功能 | 支付+配额+推送 | 多席位+导出+发票+运营后台 | API 网关+计量计费+SLA |
| 现金流 | 小额高频 | 大额年付（主力） | 项目制 |
| 规模天花板 | 中 | 高 | 极高但窄 |
| 起步难度 | 低 | 中 | 高（需数据量/质量达标） |
| 与现有架构距离 | 近 | 中 | 远 |

### 4.2 推荐组合与阶段映射

```
M1 ──► 个人会员上线（验证付费意愿 + 积累付费用户池）
M1 末 ─► 企业订阅开放（用个人付费数据筛选种子企业客户）
M2 ──► 数据 API 开放（数据量 ≥ 千万级、质量体系就绪后启动）
```

理由：个人会员基础设施（支付+配额）与企业订阅高度复用；API 依赖的数据规模与合规体系只能后置。

### 4.3 定价体系草案（v1，上线前按转化数据校准）

**个人会员**

| 档位 | 价格 | 权益 |
|---|---|---|
| 免费 | 0 | 每日 3 次搜索；仅标题 + 摘要；无联系方式/附件/推送/导出 |
| 黄金 | 39 元/月 或 299 元/年 | 正文全文、每日 20 次搜索、站内收藏 |
| 铂金 | 99 元/月 或 799 元/年 | 黄金全部 + 查看联系方式/附件 + 3 组关键词订阅推送（每日邮件）+ 每日 20 条导出 |

**企业订阅**

| 档位 | 价格 | 权益 |
|---|---|---|
| 标准 | 6800 元/年 | 3 席位、全员铂金权益、10 组关键词推送、每月 2000 条导出 |
| 专业 | 16800 元/年 | 10 席位、不限导出、30 组推送、行业包（医疗/IT 等）、专属客服 |
| 旗舰 | 定制 | 专业全部 + API 访问 + 专属数据源需求受理 + SLA |

**数据 API**：0.02–0.05 元/次阶梯计价，月套餐 1999 元起（5 万次），按字段分级（基础字段/含联系方式/含历史库）。

### 4.4 免费漏斗与付费墙

- **免费层价值**：每日 3 次全文搜索 + 标题摘要，保证 SEO 与口碑传播基本盘（对标千里马「7 天前免费」的引流逻辑，我们以「搜索次数」而非「时间」控墙，对新站冷更友好）
- **付费墙位置**（按付费意愿强度排序，逐层解锁）：①联系方式（最强，千里马同款强付费点）②正文全文 ③附件 ④订阅推送 ⑤导出
- **转化钩子**：免费用户命中关键词的新公告 → 邮件送达「您有 3 条新商机，升级查看详情」

## 第五章 数据采集升级

> 本章对应需求「数据信息更丰富、来源更多、精细化的来源配置管理、与数据源对应的采集技能」。

### 5.1 数据丰富化

**Tender 字段扩展**（Prisma migration，逐字段）：

| 字段 | 类型 | 说明 | 采集来源 |
|---|---|---|---|
| projectNo | String? | 项目/采购编号 | 列表/详情正则 |
| budgetAmount | Decimal? | 预算金额（元） | 详情正则 + 表格 |
| awardAmount | Decimal? | 中标金额（元） | 中标公告正文 |
| openTime | DateTime? | 开标时间 | 详情正则 |
| industryCode | String? | 行业分类（字典表） | 规则分类 + 人工运营 |
| winningSupplier | String? | 中标供应商 | 中标公告正文 |
| contentHtml | Text? | 原文 HTML 快照 | 详情抓取时原样存储 |
| projectRefId | Int? | 关联 Project 主数据 | 聚合逻辑 |

**新模型**：

- `Project`（项目主数据）：同一项目的「招标 → 变更 → 中标」公告聚合为一个项目视图，聚合规则 = 项目编号精确匹配 + 标题相似度（编辑距离/关键词重合）兜底，人工合并入口放后台
- `Attachment`：tenderId / name / url / storageKey / size / contentType——附件下载入对象存储（本地目录起步），供付费会员下载
- `OrgContact`：orgName / phone / email / address——从公告「联系方式」小节（已有解析器）+ 正则 + 表格抽取，采购人与代理机构各一条，供铂金以上查看

**数据质量体系**：

- 字段置信度：规则抽取 0.8、人工录入/校对 1.0、跨源一致 1.0；前台展示「未标注置信度的金额仅供参考」
- 多源仲裁：同一字段多来源冲突时按 `CrawlSource.priority` 高者优先，其余值保留为字段历史
- 字段级来源标注：每个关键结构化字段记录来源 skillCode，前台可展开「数据来源」

### 5.2 来源扩展

**优先级矩阵**（接入顺序按「价值 ÷ 接入成本」排序）：

| 优先级 | 来源 | 类型 | 覆盖 | 结构/反爬评估 | 预估接入 |
|---|---|---|---|---|---|
| P0 | 全国公共资源交易平台体系（31 省平台，逐省接入） | 混合（部分有 json 接口） | 工程+政采全量，价值最高 | 结构差异大、部分需 cookie；逐个攻克 | 0.5–2 天/省 |
| P0 | 中国招标投标公共服务平台 | 接口 | 全品类聚合 | 有验证码风险，需评估 | 2–3 天 |
| P1 | 央企电商采购平台（国家电网、中石化易派客、南方电网等 5–8 个） | 混合 | 高客单价商机 | 反爬较强 | 2–3 天/个 |
| P1 | 军队采购、高校/医院专项 | html | 垂直深耕素材 | 相对简单 | 1–2 天/个 |
| P2 | 地方政采分网细化、采购意向专项（对标千里马 999 元/年产品线） | html/json | 提前商机 | 中 | 按需 |

**目标节奏**：M0 末 6 源（日增 ≥500 条）→ M1 末 10+ 源（日增 ≥1500 条）→ M2 20+ 源。

### 5.3 采集技能体系 v2

**问题**：当前 `parse.fields` 是封闭的 7 字段对象（`crawler/types.ts`），`ParsedItem` 硬编码 8 字段，`upsertTender` 的 data 也是硬编码集合——每新增一个业务字段需同时改 types.ts、runner.ts、schema 三处，无法「映射即生效」。

**v2 设计**：

1. **声明式 extraFields 通道**：`parse.fields` 增加开放式扩展区，映射写法与现有 FieldSpec 完全一致；执行器把 extraFields 原样并入入库数据（按白名单校验目标列），新增字段零代码变更：

```yaml
lists:
  - type: NOTICE
    mode: html
    url: "https://ggzy.example.gov.cn/jyxx/{page}.html"
    parse:
      itemSelector: ".ewb-list li"
      fields:
        title: { selector: "a" }
        url: { selector: "a", attr: "href" }
        date: { selector: ".date", regex: '\d{4}-\d{2}-\d{2}' }
        province: "河南"            # 常量直接可用
      extraFields:                  # v2 新增
        projectNo: { selector: ".code" }
        budget: { selector: ".amount", regex: '([\d,.]+)\s*万?元' }
```

2. **detail.extraction 结构化抽取**：从详情页（含正文表格）抽取结构化字段，选择器 + 正则双通道：

```yaml
    detail:
      contentSelector: ".ewb-article"
      extraction:                   # v2 新增
        expireDate: { regex: '递交.{0,8}文件.{0,20}?(\d{4}年\d{1,2}月\d{1,2}日)' }
        budgetAmount: { regex: '预算金额[（(]?(元)?[）)]?[：:]\s*([\d,.]+)' }
        contactPhone: { regex: '(?:联系电话|电\s*话)[：:]\s*([\d\-—()]{7,})' }
        winningSupplier: { regex: '中标(?:供应商|人)[：:]\s*([^\s，,。]{4,40})' }
```

3. **技能包版本化**：config.yaml 内容入库 `SkillRevision`（版本号/修改人/备注/diff），后台可对比与一键回滚；线上生效版本与文件系统解耦（DB 为准，文件仅作开发态）
4. **dry-run 测试模式**：`POST /api/crawl/test {skillCode, maxPages:1, dryRun:true}` 返回解析样例（前 N 条字段值 + 抽取结果），不落库；配合配置校验器（YAML schema 校验 + 选择器探活）实现「先测后存」
5. **SKILL.md 规范升级**：新增「字段抽取口径」章节模板，站点改版修复时同步更新抽取正则

### 5.4 采集配置中心

**CrawlSource 模型扩展**：

| 字段 | 说明 |
|---|---|
| scheduleCron | 每源独立调度（默认按源类型分档：高频源每 2h、中频每 6h、低频每日） |
| rateLimitQps / concurrency | 全局限速与并发上限（与 config.yaml 的 requestDelayMs 合并生效） |
| proxyPolicy | off / pool 名称（为反爬强的源预留） |
| priority | 多源仲裁优先级 + 调度优先级 |
| healthScore / consecutiveFailures | 健康分与连续失败计数 |
| configVersion | 当前生效的技能包版本 |

**管理界面**（`/admin/sources` 升级 + 新页）：

- 源列表：健康分徽章、今日增量、数据新鲜度（距上次成功抓取时长）、7 日趋势迷你图
- 新建/编辑源：表单模式（基础信息/调度/限速/代理/告警）+ YAML 编辑器模式，保存即校验 + 热更新（worker 每轮开始时从 DB 读最新版本）
- dry-run 预览页：解析样例表格 + 抽取字段高亮，通过后才允许保存
- 版本历史：diff 对比 + 回滚
- 告警规则页：按源/全局配置阈值

**健康分算法（草案）**：

```
score = 100
      − consecutiveFailures × 15          （连续失败）
      − failRate7d × 40                   （近 7 日失败率）
      − (now − lastSuccessAt > 2 × 调度周期 ? 20 : 0)   （新鲜度超期）
分级：≥90 健康（绿）/ 70–89 观察（黄）/ <70 失效（红，触发告警）
```

**告警通道**：邮件 + 企业微信 webhook；触发条件：健康分 <70、单次运行 0 解析、连续 3 次失败。CrawlLog 扩展 httpOk/httpFail/itemsParsed/avgLatencyMs 用于统计。

**调度器**：从「全局单 cron」升级为 DB 队列 + 按源 cron（node-cron 动态注册）+ 失败指数退避（连续失败翻倍间隔）+ 全局并发上限（防打爆目标站与自身带宽）。

## 第七章 技术架构演进

原则：**分期渐进，每期只做当下必需的升级**，避免一次性重写。

| 项 | 现状 | 演进 | 时机 | 理由 |

## 第八章 合规与风险

### 8.1 数据来源合规基线（红线，全程执行）

1. **只采集依法应当公开的信息**：招标公告、中标结果、更正公告等法定公开内容；不触碰需登录/付费才能获取的数据
2. **遵守 robots 与站点规则**：礼貌抓取（限速/UA 标识/低频），不破解验证码、不伪造登录态、不做对抗性突破——这也是对竞对诉讼风险的根本规避
3. **来源标注与原文链接**：每条公告保留 sourceName + sourceUrl 并显著展示（现状已具备，制度化写入用户协议）
4. **个人信息处理**：采购人/代理机构的联系方式属于公开的机构联络信息，仍需：仅展示给付费会员、提供纠错与删除请求通道、隐私政策明示来源与用途
5. **不采买灰色数据**：不采购来路不明的数据库，历史库以自采累积为主

### 8.2 资质路径

| 资质 | 时机 | 说明 |
|---|---|---|
| ICP 备案 | M1 上线前 | 非经营性备案，前置条件 |
| EDI / 经营性 ICP 许可 | M1–M2（收费业务规模化前） | 经营性网站收费需持证 |
| 等保二级 | M2 | 企业客户采购流程常要求提供 |

### 8.3 法律文本清单（M1 上线前完成）

用户服务协议（含数据来源与免责声明）、隐私政策、退费规则、企业服务合同模板、API 接入协议。建议委托律师起草基础版本（一次性预算见第十章）。

### 8.4 竞对与舆情风险

- 竞对可能以「不正当竞争」发难：应对 = 8.1 红线全守 + 不使用竞品名称做对比广告 + 保留自采过程证据（抓取日志即合规证据）
- 数据准确性纠纷：前台明示「信息以官方原文为准」，提供纠错入口，重大纠错 SLA 24h

### 10.4 盈亏平衡测算（三情景，月度）

固定月成本 ≈ 基础设施 1000 + 人力 20000（按 1.5 人综合）≈ **21000 元**。

| 情景 | 构成 | 月收入 | 结论 |
|---|---|---|---|
| 悲观 | 个人付费 100 人 ×33 元均 | ≈3300 元 | 覆盖基础设施，需压缩人力投入 |
| 基准 | 个人 300 人 ×33 + 企业 2 家标准档（6800/年 ≈ 567/月） | ≈9900 + 1133 ≈ **11000 元** | 覆盖基础设施与约一半人力，模式初步验证，需加快企业获客 |
| 乐观 | 个人 800 人 + 企业 5 家（专业档月摊 1400） | ≈26400 + 7000 ≈ **33400 元** | 越过盈亏平衡，进入正循环 |
