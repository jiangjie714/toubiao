> **版本**：v1.0 · 2026-10-17

## 一、一句话结论

工程完成度极高，商业完成度接近于零。**当前最大风险不是"功能不够"，而是"用工程完备度掩盖了商业验证的缺席"。**
第一优先级：**停止拉新功能，把 80% 精力转到"把第一个真实客户的钱合法收进来并留住"。**

## 二、现状盘点（证据化）

### 2.1 已经很强（工程/产品）
- 商业化全链路：`Plan / Subscription / Order / Invoice / QuotaLedger / ApiKey`（`prisma/schema.prisma`）
- 收款四通道：Jeepay 聚合 + 支付宝 + 微信 + 对公转账（`src/lib/payments.ts`、`payment-prepay.ts`、`payment-notify.ts`）
- 企业协同：多席位 `Team`、RBAC 动态菜单权限（`Role / Permission / Menu`）、企微/钉钉/飞书 Webhook 路由（`webhook-dispatcher.ts`）
- 数据工具：AI 标讯速读、标书清标、标书装配、竞对雷达、保证金台账、资质预警、复盘归因
- 采集体系：24 个 Skills 数据源、配置中心与版本化、熔断探针（`crawler/skills/`、`lib/crawler/`）
- 运维底座：PostgreSQL 迁移、Docker Compose 生产拓扑、合规中心

### 2.2 商业关键短板（真实缺口）
| 维度 | 证据 | 判断 |
|---|---|---|
| 生产上线 | `.env` `APP_URL` 仍为 localhost；`docker-compose` 默认裸 IP `http://124.220.98.81:3000`，无域名/HTTPS | **未真正上线** |
| 邮件通道 | `.env` 未配置 `SMTP_HOST` → 邮件只打日志（`src/lib/mailer.ts`） | **注册验证/推送在生产是死的** |

| 合规资质 | ICP/EDI/等保二级在文档中仍为"待办" | **收费业务前置条件未就绪** |

## 三、CEO 视角的六个致命问题

1. **建设顺序反了**：无付费用户就先造企业 CRM/标书装配/竞对雷达。这些是"有 10 家企业客户后"的工具。
2. **护城河认错**：本行业护城河是**数据**（覆盖 × 新鲜度 × 准确度），不是功能。功能可被两周抄走，历史库/全量源抄不走。
3. **还不能合法收钱**：无域名/HTTPS/备案/EDI，SMTP 未配 —— 用户连注册验证邮件都收不到。
4. **支付是临时方案**：个人收款码 + 人工核销，用于收 B 端几千上万元年费，财务与合规双重不成立、不可规模化。
5. **功能=负债**：`src/components/site-nav.tsx` 暴露 30+ 导航项，首屏认知负担过重，稀释"找标"核心价值。
6. **没有增长引擎**：SEO 矩阵、微信生态仅"能力就绪"，无内容与渠道执行 —— 产品造了，公司还没开始卖。

## 四、战略取舍：砍 / 保 / 加

### 4.1 冻结/后置（代码保留，入口收敛）
企业 CRM 漏斗、标书装配、标书质检、竞对雷达、复盘归因、等保中心、业绩库、报价罗盘、投标日历
→ 全部收进"企业版·内测"，前台导航不暴露，避免稀释核心路径。

### 4.2 死守并做深（唯一核心竞争力 = 一条闭环 + 数据 + 合规）
1. **核心闭环**：搜索 → 命中 → 看联系方式/附件 → 邮件/微信推送。做到"又快又准又全"。
2. **数据覆盖与质量**：24 源 → 全国 31 省 ggzy 全量；去重、字段抽取准确度、`projectNo` 聚类。
3. **合规可运营**：域名+HTTPS+ICP/EDI、SMTP、正式对公收款。

### 4.3 必须新增（缺失的另一半公司 = GTM）
- 规模化 SEO 落地页内容流水线（技术已有，缺内容生产）
- 微信服务号生态（登录 + 模板消息，国内该类产品最高转化触达）
- 创始主导的前 10 家企业客户直销

## 五、90 天商业化落地路线

### 阶段 A（第 1–2 周）｜让系统"能合法运营"
> 不做完这个，后面全是空转。

- [ ] 购买域名 + 配置 HTTPS + ICP 备案，`APP_URL` 改为生产域名
- [ ] 配置 `SMTP_*`，用真实邮箱跑通「注册验证码 → 注册成功 → 关键词推送」
- [ ] 落地正式对公收款（聚合支付商户号 / 企业收款码），人工核销降级为兜底
- [ ] 明确 EDI/经营性许可路径与时间表
- **验收**：任意真实用户可在公网 HTTPS 域名完成注册 → 收到验证邮件 → 收到一次推送 → 完成一次真实支付。

### 阶段 B（第 3–6 周）｜打磨单点价值，启动获客
- [ ] 前台收敛到核心闭环，弱化企业模块入口（`site-nav.tsx` 瘦身）
- [ ] 数据冲刺：接入省市级公共资源交易平台，日增 500 → 3000 条，抽检字段准确率
- [ ] SEO 落地页矩阵（省份 × 类型）批量上线
- [ ] 微信服务号登录 + 模板消息推送上线
- **验收**：自然搜索开始带来注册；推送打开率可测；数据抽检准确率 ≥ 95%。

### 阶段 C（第 7–12 周）｜拿到前 10 个付费客户（生死线）
- [ ] 免费层 + 邮件/微信钩子做漏斗，创始人亲自跟进每条试用线索
- [ ] 跑通首笔个人月付、首笔对企业公年付合同（合同 + 6% 专票闭环）
- [ ] 用真实客户反馈决定下一版本做什么，而非继续堆功能
- **验收**：≥ 1 笔个人订单 + ≥ 1 笔企业订单；MRR 首次非零。

## 六、北极星指标（替换"功能完成度"）

| 类别 | 指标 |
|---|---|
| 唯一真指标 | 月度经常性收入（MRR）、付费客户数 |
| 漏斗 | 注册转化率、免费→付费转化率、推送打开率、续费率 |
| 数据健康 | 日新增条数、字段抽取准确率、源可用率、查询命中率 |
| **明确放弃** | 以"已实现功能数 / 代码行数"衡量进度 |

## 七、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 现金烧在无客户的功能上 | 高 | 冻结新功能，成本只投 GTM 与数据 |
| 合规爆雷（无资质收费/个人码收 B 端） | 高 | 前置 ICP/EDI，启用正式商户号 |
| 数据无竞争力（覆盖窄/更新慢） | 高 | 重仓全国源，先做深 1–2 个行业 |
| 竞对法律风险 | 中 | 只采公开信息、限速、标注来源、保留抓取日志 |
| 个人付费转化不及预期 | 中 | 重心快速转向企业订阅（盈亏平衡关键变量） |

## 八、给创始人的一句话

你现在不是缺一个 CTO，是缺一次**自我克制**：砍掉 80% 已经造好的东西，用剩下 20% 换回第一张真实的付款截图。
**商业化的落地不发生在 `src/`，发生在你的银行账户里。**
